💡 Motivation 02

Why Do Functions Exist?

Feel the problem. Then the solution makes perfect sense.

😰 Without functions — repetition everywhere

You need to show a greeting for three different users:

// For Ayaan: print("Hello, Ayaan! Welcome back."); print("You have 3 new messages."); // For Sara: print("Hello, Sara! Welcome back."); print("You have 3 new messages."); // For Rafi: print("Hello, Rafi! Welcome back."); print("You have 3 new messages."); // Same logic, copy-pasted 3 times. What if the message changes? // You'd need to find and fix every single copy. 😩

✅ With a function — write once, call anywhere

void greet(String name) { print("Hello, $name! Welcome back."); print("You have 3 new messages."); } greet("Ayaan"); // Hello, Ayaan! Welcome back. greet("Sara"); // Hello, Sara! Welcome back. greet("Rafi"); // Hello, Rafi! Welcome back.

Change the message in one place, fix it everywhere instantly.

🍳 Functions are like recipes. You don’t rewrite “how to make tea” every morning. You follow the recipe once, name it, and call it whenever you want tea. The function is the recipe; calling it is making the tea.

🔧 Functions 04

Parameters

Parameters are the inputs a function accepts. Dart has several flavours — each with a clear purpose.

🗂️ Choose a parameter type

📞 Think of named parameters like ordering food: positional = “large, pepperoni, thin crust” (order matters); named = “size: large, topping: pepperoni, crust: thin” (order doesn’t matter, labels do). Named parameters make call sites self-documenting.
🔧 Functions 05

Required & Optional Named

Named parameters can be declared as required (must be passed) or optional (have a default). This is extremely common in Flutter widgets.

📐 required vs optional named

// required: caller MUST provide this argument void createAccount({ required String username, // must pass required String email, // must pass bool isAdmin = false, // optional — defaults to false int maxPosts = 100, // optional — defaults to 100 }) { print("Created: $username, admin=$isAdmin, maxPosts=$maxPosts"); } createAccount( username: "ayaan_dev", email: "[email protected]", ); // Created: ayaan_dev, admin=false, maxPosts=100 createAccount( username: "sara_admin", email: "[email protected]", isAdmin: true, maxPosts: 500, ); // Created: sara_admin, admin=true, maxPosts=500

💡 Why this matters in Flutter

// Flutter widgets use named parameters everywhere Text( "Hello World", // positional (the text) style: TextStyle( fontSize: 24, // named, optional fontWeight: FontWeight.bold, // named, optional color: Colors.blue, // named, optional ), ) // All named → you can pass in any order, skip any optional one

🏹 Arrow & Lambda 07

Arrow Syntax =>

When a function body is a single expression, you can replace { return expr; } with the shorthand => expr. Same result, less noise.

⚖️ Before and after

Standard syntax

int add(int a, int b) { return a + b; } bool isEven(int n) { return n % 2 == 0; } String greet(String name) { return "Hello, $name!"; }

Arrow syntax (identical)

int add(int a, int b) => a + b; bool isEven(int n) => n % 2 == 0; String greet(String name) => "Hello, $name!";

📐 Arrow with named parameters & in practice

// Arrow + named parameters double tax({required double price, double rate = 0.15}) => price * rate; print(tax(price: 1000)); // 150.0 print(tax(price: 500, rate: 0.05)); // 25.0 // Very common in List methods (sort, where, map) List<int> nums = [5, 1, 3, 2, 4]; nums.sort((a, b) => a - b); print(nums); // [1, 2, 3, 4, 5]
✏️ Rule of thumb: if the entire body is one expression that produces a value, arrow it. If it has multiple statements, variable declarations, or conditionals — keep the curly braces.
🏹 Arrow & Lambda 08

Anonymous Functions & Lambdas

Functions without names. You create them on the spot and pass them around like values — especially to other functions.

📋 Analogy: You hire a contractor with a specific skill for one job. You don’t give them a permanent contract — they just do the task and leave. An anonymous function is that contractor: defined for one purpose, used immediately, not stored anywhere permanently.

📐 Syntax & examples

// Named function (has a name, stored permanently) int square(int x) => x * x; // Anonymous function (no name, passed inline) List<int> nums = [1, 2, 3, 4, 5]; // Passed to forEach — no name, used immediately nums.forEach((int n) { print(n * n); }); // Arrow shorthand — same thing, one line nums.forEach((n) => print(n * n)); // Stored in a variable (a "lambda") var double = (int x) => x * 2; print(double(7)); // 14

🔁 Where you’ll see them everywhere

List<int> scores = [72, 45, 88, 91, 60]; // .where() — filter: keep scores >= 70 var passing = scores.where((s) => s >= 70); print(passing.toList()); // [72, 88, 91] // .map() — transform: double every score var doubled = scores.map((s) => s * 2); print(doubled.toList()); // [144, 90, 176, 182, 120] // .reduce() — combine: sum all scores int total = scores.reduce((sum, s) => sum + s); print(total); // 356

⏳ Async 10

Why Does Async Exist?

Before writing a single async keyword, understand the problem it solves.

🧊 The freezing problem

Imagine your app needs to load a user profile from a server. That request takes 2 seconds. If your code is synchronous, it waits — completely frozen — for those 2 seconds. The screen doesn’t update. Buttons don’t respond. The user thinks the app crashed.

// SYNCHRONOUS — everything freezes for 2 seconds String profile = fetchUserFromServer(); // ← blocks here print("Got profile: $profile"); // runs after 2s print("Updating UI..."); // runs after 2s // During those 2 seconds: the app is completely frozen

🚶 Synchronous

Do Task A. Wait. When done, do Task B. Wait. When done, do Task C.

Like a restaurant where the waiter takes your order, then walks to the kitchen and just stands there until your food is ready.

⚡ Asynchronous

Start Task A. While waiting, do Task B and Task C. When A finishes, handle its result.

Like a waiter who takes your order, gives it to the kitchen, then serves other tables while your food cooks.

☕ The real-world version: You put the kettle on. You don’t stand frozen at the kettle. You make toast while the water boils. When the kettle beeps, you handle it. That’s async — start something slow, keep moving, handle it when it’s done.

⏳ Async 12

Introduction to Future

A Future is Dart’s way of representing a value that doesn’t exist yet but will arrive later.

🎟️ A Future is a ticket stub. When you order food at a restaurant, you get a ticket. You don’t have the food yet — you have a promise that it will arrive. You can go sit down, talk to friends, check your phone. When your number is called, you collect the food. The ticket is the Future; collecting the food is .then().

📐 Declaring and creating a Future

// A function that returns a Future promises it will // eventually give back a String Future<String> fetchUsername() { return Future.delayed( Duration(seconds: 2), // simulate a 2s network call () => "ayaan_dev", // value that arrives after 2s ); } // Three possible states a Future can be in: // 1. Pending — still waiting (request in flight) // 2. Completed — succeeded, value available // 3. Error — failed (network down, server error, etc.)

A Future travels exactly one of two paths: it either completes with a value (.then) or fails with an error (.catchError). It can never do both.

⏳ Async 13

.then() & .catchError()

Two methods that let you react to a Future completing — one for success, one for failure.

📐 Basic usage

Future<String> fetchUser() => Future.delayed(Duration(seconds: 2), () => "Ayaan"); // .then() — runs when the Future SUCCEEDS fetchUser() .then((username) { print("Welcome, $username!"); // Welcome, Ayaan! }) .catchError((error) { print("Failed: $error"); // if network fails }); print("This runs IMMEDIATELY"); // prints first, before Welcome

🔗 Chaining .then() calls

// .then() returns another Future — so you can chain fetchUser() .then((username) { print("Got user: $username"); return fetchUserScore(username); // returns another Future }) .then((score) { print("Score: $score"); // runs after second Future }) .catchError((e) { print("Something went wrong: $e"); // catches ANY error in chain }) .whenComplete(() { print("Done, success or fail"); // always runs });
🏭 Think of it as an assembly line. Each .then() is a station that receives the output from the previous station and does something with it. If any station fails, the error skips straight to .catchError().

// A complete async workflow using everything from today // Named params + arrow + Future Future<Map<String, dynamic>> loadProfile({ required String userId, bool includeScores = true, }) => Future.delayed( Duration(seconds: 1), () => { "name": "Ayaan", "score": includeScores ? 92 : null, }, ); // Call it — sync lines run immediately, .then() waits loadProfile(userId: "u42") .then((profile) { String name = profile["name"] as String; int? score = profile["score"] as int?; print("Loaded: $name, score=$score"); // Lambda on result data var tags = ["flutter", "dart", "mobile"]; var upper = tags.map((t) => t.toUpperCase()).toList(); print(upper); // [FLUTTER, DART, MOBILE] }) .catchError((e) => print("Error: $e")) .whenComplete(() => print("Request complete")); print("App UI is live"); // prints first!
